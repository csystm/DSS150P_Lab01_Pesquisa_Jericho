# Reflection

1. `products.parquet` would be easiest to integrate. It is already in a structured format, has no missing values, no duplicates, and a clean unique `product_id`. The Parquet metadata also preserves data types, which reduces the need for manual parsing. A pipeline could read it directly with pandas or Spark and load it into a table with minimal transformation. Although `orders.json` also has a unique `order_id` and no missing values, it contains a nested `shipping` object that must be flattened before loading which adds an extra step. The PostgreSQL `support_tickets` table is already relational but it requires a live database connection and careful handling of timestamps. `products.parquet` avoids these complexities.

2. `customers.csv` presents the greatest risk. Based on profiling, there are 2 fully duplicated rows and only 247 distinct `customer_id` values out of 250, meaning the identifier is not unique. Additionally, `email` and `city` contain missing values, and `signup_date` is stored as a string instead of a date. These issues require cleaning, deduplication, and type casting before the data can be reliably used.

3. Building before understanding the schema can lead to some failures that are hard to detect. Duplicate records might inflate metrics, missing values could break joins, and type mismatches may cause crashes. A data contract defines expectations for keys, nullability, and value ranges. Without it, downstream consumers may receive incorrect data, and schema changes from the source could go undetected. Detecting these issues early through profiling and a contract is far cheaper than fixing them after they have propagated into downstream reports.

4. Git tracks changes and allows rollback to a known state. Virtual environments isolate Python dependencies which helps prevent version conflicts. Containers package the database and its configuration which ensures everyone runs the same PostgreSQL version and settings. Documentation records setup steps, source metadata, and known issues, and these help reduce onboarding time and make the pipeline easier to debug and maintain. Together, these practices create a reliable and traceable environment where any team member can reproduce results and trust the data.
